# Auditoria — Alien Client e launcher — 26/10/2026

**Resultado: manter a classificação alpha.** Foram encontrados **um problema de prioridade alta e quatro de prioridade média**, além de três observações menores. As suítes existentes passaram, mas não cobriam os casos abaixo. Esta auditoria registra falhas e reproduções; **não corrige o produto**.

Estado auditado: `8bf23165744e0fc630689c1de76ca0b6316a191c`, **Unified 0.6.0-alpha.2 / launcher 0.3.0-alpha.2**. Trabalho isolado em `audit/alien-client-20261026`, [PR #20](https://github.com/AttackAlien/Alien-Client/pull/20), baseado no PR #19. Código de produção, artefatos publicados, perfis de usuários e galeria aprovada foram preservados. Sem merge na main.

### A1 — sobrescrita de perfil de configuração

Em [ConfigStore.java:70](https://github.com/AttackAlien/Alien-Client/blob/8bf23165744e0fc630689c1de76ca0b6316a191c/src/main/java/dev/alien/client/config/ConfigStore.java#L70), `loadProfile(B)` substitui `current` e chama `save()`. A função [save:47](https://github.com/AttackAlien/Alien-Client/blob/8bf23165744e0fc630689c1de76ca0b6316a191c/src/main/java/dev/alien/client/config/ConfigStore.java#L47) continua usando `activeServerProfile=A` como destino. O resultado é gravar B sobre `profiles/A.json`, mantendo a associação do servidor com A.

A biblioteca da interface chama essa API em **Load profile** e informa que o perfil selecionado está em uso; não pede autorização para sobrescrever outro perfil. O teste reproduziu:

```text
BOUND_PROFILE_BEFORE=Original server A
BOUND_PROFILE_AFTER=Personal B
BINDING_AFTER=server_A
UNRELATED_PROFILE_OVERWRITTEN=true
```

Impacto: perda silenciosa das configurações anteriormente salvas em A. **Correção recomendada:** separar ativação de perfil e persistência no perfil vinculado; preservar A e exigir uma ação explícita antes de sobrescrevê-lo. Acrescentar regressão para carregar B com A ativo.

[Evidência](audit-results/2026-10-26/java-profile-reproduction.txt) · [Reprodutor com a API real](../tools/audit/JavaProbe/ConfigAuditProbe.java).

### A2 — recuperação de configuração incompleta

[LauncherProfile.cs:46](https://github.com/AttackAlien/Alien-Client/blob/8bf23165744e0fc630689c1de76ca0b6316a191c/launcher/AlienLauncher.Core/LauncherProfile.cs#L46) lança `InvalidDataException` para arquivos maiores que 16.384 bytes. O `catch` seguinte só aceita `IOException` ou `JsonException`. Em .NET 8, `InvalidDataException` **não herda de IOException**, como confirmou o probe. O construtor da janela chama `Load()` sem tratamento externo.

Reprodução: JSON válido `{"MemoryMb":4096}` seguido de 17.000 espaços. `LauncherPreferences.Load()` lança `System.IO.InvalidDataException`; a recuperação para padrões não ocorre.

Impacto: o launcher não abre até intervenção no arquivo local. **Correção recomendada:** tratar explicitamente a rejeição por tamanho, preservar a configuração rejeitada e carregar padrões, com diagnóstico recuperável. O teste existente cobre JSON inválido, mas não arquivo grande.

[Evidência](audit-results/2026-10-26/launcher-probe.json) · [Probe .NET](../tools/audit/LauncherProbe/Program.cs).

### A3 — perfil Vanilla salvo não é restaurado

[Program.cs:139](https://github.com/AttackAlien/Alien-Client/blob/8bf23165744e0fc630689c1de76ca0b6316a191c/launcher/AlienLauncher/Program.cs#L139) inclui apenas cinco versões Vanilla na abertura. **Atualizar versões** pode acrescentar outras versões oficiais, mas elas não são reconstruídas ao reiniciar. Em [Program.cs:164](https://github.com/AttackAlien/Alien-Client/blob/8bf23165744e0fc630689c1de76ca0b6316a191c/launcher/AlienLauncher/Program.cs#L164), não encontrar a seleção salva escolhe silenciosamente `Items[0]`, o Alien.

Reprodução no desktop Windows Server 2022:

- Controle: Vanilla **1.21.1** foi restaurado corretamente e permaneceu Vanilla após fechar.
- Caso: Vanilla **1.21.4** salvo abriu como **Alien / 1.8.9**; ao fechar, `settings.json` passou a conter `Alien=true`, `Version=1.8.9`.

Impacto: o usuário volta para outro jogo/perfil sem aviso. **Correção recomendada:** preservar a versão salva válida na lista antes de selecionar e atualizar os lançamentos oficiais sem destruir a preferência existente.

[JSON observado](audit-results/2026-10-26/windows-profile-evidence.json) · [Probe da janela de produção](../tools/audit/WindowsProbe/Program.cs) · [Coleta Windows](https://github.com/AttackAlien/Alien-Client/actions/runs/40347200344). O job concluiu a coleta; o campo `profileRestored=false` é uma falha do produto, não uma aprovação de funcionamento.

### A4 — miniatura é validada depois da alocação

[ProfileLibraryScreen.java:27](https://github.com/AttackAlien/Alien-Client/blob/8bf23165744e0fc630689c1de76ca0b6316a191c/src/main/java/dev/alien/client/studio/ProfileLibraryScreen.java#L27) chama `ImageIO.read()` antes de verificar largura/altura. Arquivos rejeitados não entram em cache. Como `photo()` é chamado pelo desenho da tela, o mesmo arquivo volta a ser decodificado a cada quadro.

Foi gerado um **PNG sintético de teste**, 6000×6000, com **105.048 bytes**, abaixo do limite de arquivo aceito. O probe invocou o **método privado real** `ProfileLibraryScreen.photo` por reflexão, com armazenamento descartável e sem inicializar Minecraft/OpenGL:

- Com heap de 256 MiB: três chamadas levaram aproximadamente **1.196 ms** no ensaio inicial e deixaram zero texturas em cache; cada chamada rejeita a imagem somente após decodificá-la.
- Com heap de 64 MiB: o método retornou sem cache. Uma observação separada do decoder confirmou `IIOException` causada por `OutOfMemoryError` antes do teste de dimensões. Essa exceção é capturada pelo método e a tentativa se repete.

**Não foi comprovada queda do jogo.** A falha confirmada é validar tarde e repetir trabalho caro; os tempos do probe headless não são um benchmark de FPS do Minecraft. O arquivo também poderia ser uma captura legítima de resolução acima de 4096 pixels.

**Correção recomendada:** consultar dimensões com `ImageReader` antes de ler pixels e memorizar rejeições por arquivo/modificação. O projeto já aplica validação antecipada em `SkyboxLoader` e `CosmeticAssets`.

[Método real, heap 256 MiB](audit-results/2026-10-26/thumbnail-method-256m.txt) · [Heap 64 MiB](audit-results/2026-10-26/thumbnail-method-64m.txt) · [Observação complementar do decoder](audit-results/2026-10-26/thumbnail-decoder-64m.txt) · [Reprodutor sem cópia do método de produção](../tools/audit/JavaProbe/ThumbnailAuditProbe.java).

### A5 — lacuna nos gatilhos de CI

[unified-client-ci.yml:4](https://github.com/AttackAlien/Alien-Client/blob/8bf23165744e0fc630689c1de76ca0b6316a191c/.github/workflows/unified-client-ci.yml#L4), `forge-ci.yml` e `sky-studio-ci.yml` filtram `pull_request` para base `main`. Entretanto:

| PR | Base atual |
| --- | --- |
| #16 | `feature/hud-studio-ultimate-20261023` |
| #17 | `feature/cosmetic-trails-polish-20261023` |
| #18 | `feature/visual-scenes-20261024` |
| #19 | `feature/interactive-studio-20261024` |

Alterar Java nesses PRs encadeados não dispara automaticamente o CI principal. O CI do launcher possui seu próprio gatilho e não executa a suíte Java.

**Há execuções manuais aprovadas para a versão atual.** Este achado não invalida esses resultados; aponta a ausência de uma guarda automática para novas alterações. **Correção recomendada:** cobrir os PRs encadeados, ao menos com compilação/JUnit, e associar a aprovação ao SHA efetivamente integrado.

## Observações menores

- **O1 / P3:** [RuntimePolicy.cs:22](https://github.com/AttackAlien/Alien-Client/blob/8bf23165744e0fc630689c1de76ca0b6316a191c/launcher/AlienLauncher.Core/RuntimePolicy.cs#L22) ignora o código de saída de `java -version`. Um wrapper sintético que imprimiu Java 8 e saiu com código 42 foi aceito. Exigir saída zero antes de validar o texto. Isso não demonstra execução remota ou bypass de autenticação.
- **O2 / P3:** a expressão de versão aceita `"1.8.9\n"`, pois `$` permite a última quebra de linha em .NET. Usar término absoluto ou validação integral do identificador. Não foi reproduzida fuga de diretório.
- **O3 / P3:** [InstanceInstaller.cs:76](https://github.com/AttackAlien/Alien-Client/blob/8bf23165744e0fc630689c1de76ca0b6316a191c/launcher/AlienLauncher.Core/InstanceInstaller.cs#L76) ainda envia `GameLauncherVersion=0.2.0-alpha.1`, embora a versão distribuída seja 0.3.0-alpha.2. Centralizar a versão para evitar diagnósticos inconsistentes.

## Reprodução

```bash
# Configurar Java 8, .NET 8 e caches conforme os guias do projeto.
ALIEN_TOOLS_DIR=/workspace/.alien-tools ./gradlew --offline --no-daemon -Pedition=unified test
ALIEN_TEST_PAYLOAD="$PWD/launcher/payload" ALIEN_TEST_JAVA8="$JAVA_HOME/bin/java" \
  dotnet test launcher/AlienLauncher.Tests/AlienLauncher.Tests.csproj
dotnet run --project tools/audit/LauncherProbe/LauncherProbe.csproj
python3 scripts/audit-local-probes.py --java-home "$JAVA_HOME" --output build/audit-local
```

O probe .NET aceita opcionalmente `<instância-descartável-já-instalada> <java8>` para construir o comando e observar a configuração de logging, sem iniciar o processo. Essa construção usa uma identidade anônima exclusiva do probe, sem autenticação Microsoft. A coleta Windows está em [alien-audit.yml](../.github/workflows/alien-audit.yml).

Todos os casos que escrevem configurações usam diretórios temporários próprios; não apontar os probes para perfis de jogadores. O PNG sintético é apenas entrada de teste, não uma captura de jogo. Nenhuma imagem ilustrativa foi apresentada como evidência visual.

## Limites e próximos passos

Esta foi uma revisão priorizada de launcher, persistência/importação de perfis, carregamento de imagens, empacotamento e CI, com execução das suítes automatizadas existentes. Não é uma revisão exaustiva de cada renderizador ou certificação de segurança de todos os componentes Java/Forge.

Login Microsoft com conta licenciada, renovação/logout real, multiplayer, gameplay em PC Windows físico, alto DPI, GPU física e compatibilidade OptiFine continuam sem validação nesta auditoria. A ausência de avisos NuGet não equivale à ausência de vulnerabilidades em todo o produto. Não houve novo teste gráfico do Minecraft.

Ordem recomendada: **A1**, depois **A2/A3**, depois **A4/A5**, adicionando regressões antes das correções. Manter a release como alpha até corrigir essas falhas e validar autenticação e execução no ambiente Windows de uso.
